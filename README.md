# WebSocket Relay Server

This is a WebSocket relay server written in Go. It acts as a bridge between two clients that cannot connect directly over a local network, pairing them via a unique session ID and proxying messages between them bidirectionally.

## Features

* **Session Pairing:** Connects two separate clients using a shared session ID provided via the URL query string.
* **Bidirectional Piping:** Automatically forwards WebSocket frames between the paired clients in real time.
* **Connection Timeout:** Automatically drops pending connections if a second peer does not join within 30 seconds, preventing memory leaks.
* **RFC Compliant:** Uses the `gorilla/websocket` package to safely read, unmask, and write frames according to WebSocket protocol standards.

---

## Getting Started

### Prerequisites

* Go installed on your machine.
* The `github.com/gorilla/websocket` package.

### Running the Server

Start the server from your terminal. You can specify the port using the `-port` flag.

```bash
go run main.go -port 8081

```

**Available Flags:**

* `-port`: Port to run the relay server on (default: `8081`).

---

## Connection Protocol

Clients connect to the server via the `/ws` endpoint. They must provide a unique `id` in the query parameters (typically the `session_id` generated by the lobby server).

### Connection URL

```text
ws://<server-address>:8081/ws?id=<session_id>

```

### Workflow

1. **First Connection:** The first client connects using the session ID. The server places this connection in a "pending" state and waits.
2. **Second Connection:** The second client connects with the exact same session ID.
3. **Bridging:** The server removes the session from the pending list and spawns two goroutines to pipe messages from Client A to Client B, and vice versa.
4. **Timeout:** If the second client fails to connect within 30 seconds of the first client, the server closes the first client's connection and deletes the pending session.
5. **Disconnection:** If either client disconnects after the bridge is formed, the read/write pipes will fail, and the server will safely close both connections.
